A cue sheet and a door guard

The stage manager cue sheet tells the performer the order of the show. A door guard at the wings stops a dangerous move even when the performer forgets the sheet.

📋

Stage manager

Holds the cue sheet and calls the order of the show.

🎤

Performer

Writes the code, then follows the cue sheet and the door guard.

🚪

Door guard

Stops a dangerous move at the wings, even when the sheet was forgotten.

In this repo the performer is an agent, and the door guard is a hook. The flower scorer from day 1 did not appear because an agent was free to improvise, so the files say what the agent may do.

The next session reads the file

A rule in a chat disappears. A rule in a file is what the next session reads, so you steer the agent by editing the cue sheet.

The door guard, line by line

guard_shell.py names the protected branches, then refuses a commit that would skip pre-commit. The lines below are the real check.

CODE 
PROTECTED = {"develop", "ppe", "main"}

    if args[0] == "git" and "commit" in args and any(arg in {"-n", "--no-verify"} for arg in args):
        return deny(
            "git commit --no-verify is blocked so pre-commit can run.",
            "Do not pass --no-verify or -n to git commit. "
            "Run `uv run pre-commit run --all-files` and commit again.",
        )
PLAIN ENGLISH

Keep three protected names: develop, ppe, and main.

 

If the command is git commit and it carries a skip-checks flag...

...refuse it, instead of letting the commit through.

Say the skip is blocked so pre-commit can still run.

Say: do not pass --no-verify or -n.

Say: run the full check, then commit again. Those two lines are one message.

That is the end of the refusal.

hooks.json runs that guard before any shell command. The list is JSON.

CODE 
    "beforeShellExecution": [
      {
        "command": "python3 plugins/iris-agent/scripts/guard_shell.py",
        "timeout": 10,
        "failClosed": false
      }
    ],
PLAIN ENGLISH

Before any shell command, open this list of guards.

Here is one guard.

Run the door-guard script so a bad command can be stopped.

Give that script up to 10 seconds.

If the script itself crashes, do not freeze every command.

End of this guard.

End of the list.
