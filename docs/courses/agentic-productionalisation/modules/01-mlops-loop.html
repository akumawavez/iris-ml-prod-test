What MLOps means here

Picture a relay with three lanes: develop, ppe, and prod. The baton is the git commit — the code — and each lane runs the same race, then writes its own result.

You do not hand a finished trophy from one lane to the next. Databricks names that rule: deploy code, not models.

Each lane is a target

The address infer loads

Infer loads a model URI: models:/catalog.schema.model@alias.

The lines below are the real parameters in the job YAML at databricks/jobs/iris_ml_job_pipeline.yml. Each variable is filled in for that target.

📍

Catalog address

              - --model-uri

PLAIN ENGLISH

Pass the --model-uri flag so infer opens an address instead of a copied file.

Join models:/, the registered name, and this lane's alias so every target fills in its own address.

The next flag names the logbook; the line above is the one that chooses the version.

Do not pass the trophy

Copying a model binary from develop into prod skips the review the code already passed. Refit in each environment. The laptop folder models/iris_species is only so local tests have an input; it is not the registry.
