Stick the spine labels

A run logs its tags, and registration then points the environment alias and Champion at the new version. These two functions are the real code in notebooks/train_register.py.

CODE 
def aliases_for_env(alias: str) -> tuple[str, ...]:    """Env alias plus Champion, de-duplicated. Empty alias yields Champion only."""    labels: list[str] = []    if alias:        labels.append(alias)    if "Champion" not in labels:        labels.append("Champion")    return tuple(labels)  def set_model_aliases(name: str, version: str, alias: str) -> tuple[str, ...]:    """Point the env alias and Champion at the registered version."""    client = mlflow.MlflowClient()    applied = aliases_for_env(alias)    for label in applied:        client.set_registered_model_alias(name, label, version)        print(f"aliased {name}@{label} -> version {version}")    return applied
PLAIN ENGLISH

A recipe that decides which spine labels to move.

Its note: add the environment label and Champion, never twice. A blank label means Champion only.

Start with an empty list of labels.

If an environment label was passed in, keep going. A blank one skips this.

Put that label on the list first — develop, ppe, or prod.

If Champion is already on the list, skip the next line so it is not stuck twice.

Add the Champion spine label.

Hand the finished labels back. The next recipe can walk them.

The next recipe talks to the shelf. It needs the model name, the version number, and the environment label.

Its note says what registration does: point the environment alias and Champion at the registered version.

Open a client — the desk allowed to move spine labels.

Ask the first recipe which labels should move.

Take those labels one at a time.

Stick this label on this version of this model. The label can move later. The version number stays on that copy.

Print one confirmation: this name, at this label, now points at this version.

Hand back the labels that moved, so the caller can see what changed on the shelf.

Challenger — passed validation, not yet the one you serve — is the Databricks idea. This repo does not have a separate task that sets Challenger yet.

How you take a copy off the shelf

Batch infer asks the shelf with a name plus a spine label. It does not open a file on a laptop.

models:/${var.registered_model_name}@${var.model_alias}

🔖

@develop

The version that environment registered. ppe uses @ppe. prod uses @prod.

🏆

@Champion

The copy batch is allowed to treat as current.

🤝

Same version

@develop and @Champion can stick to the same numbered copy. The functions above add both labels.

📝
One catalog, three schemas

Copying weights across catalogs needs a written reason, an ADR. This repo keeps one catalog, dbw_iris_ml_dev, and the schemas develop, ppe, and prod.

Tags a reviewer can filter

The reading-room log is useful when someone can filter it. These tags are written on the run.

📁
project

Which project this log line belongs to.

🚩
env

Which lane: develop, ppe, or prod.

🗂️
stage

A filter word on the log. The shelf still answers to an alias.

🏷️
alias

Which spine label this run intended to move.

☁️
compute

serverless — the kind of computer the run asked for.

📄
code_version

Which copy of the code this run used.

🔗
mlflow.source.git.commit

Filled when a git SHA exists.

A served version should trace back to a commit.

Leave secrets out of the log

🔐
DATABRICKS_HOST

Read from the process environment, the values around the run.

🔒
DATABRICKS_TOKEN

Same place. It stays out of git. Do not paste secrets into the log.
