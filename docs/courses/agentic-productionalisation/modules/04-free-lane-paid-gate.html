The gate reads the ticket

This check lives in .github/workflows/cd.yml, in YAML. Under each run, a shell command guards the gate.

CODE 
      - name: Refuse unless explicitly confirmed
        run: |
          test "${{ inputs.confirm }}" = "YES"
      - name: Match git branch to Databricks target
        run: |
          case "${{ inputs.target }}" in
            develop) expected=develop ;;
            ppe) expected=ppe ;;
            prod) expected=main ;;
            *) echo "unknown target ${{ inputs.target }}" >&2; exit 1 ;;
          esac
          test "${GITHUB_REF_NAME}" = "$expected"
PLAIN ENGLISH

Name this step so the rule is visible: no departure without an explicit yes.

The vertical bar starts a shell command on the next line.

Stop unless the typed confirm word is YES. The form starts at NO, so a quiet form does not board.

Name the next step: the git branch has to match the Databricks target on the form.

The vertical bar starts this command too.

Take the target they chose, and walk the list below.

Target develop expects git branch develop.

Target ppe expects git branch ppe.

Target prod expects git branch main.

Any other target is unknown. Print that error and stop the flight.

End of the list.

The branch this run is actually on must be that expected name. A mismatch stops the gate.
