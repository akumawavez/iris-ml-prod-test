Rules on the door

House rules posted on a workshop door stay short, because the expensive mistakes are always the same ones.

In this repo, each card is a best practice already being followed.

The shop

📁

One repo, one bundle

One git repo. One bundle for develop, ppe, and prod. Review YAML like Python.

🪜

Promotion path

feature/* to develop to ppe to main. main is the prod git branch and selects Databricks target prod. No force-push of those branches.

What leaves the bench

📄

Ship the code

Deploy code, not the model binary. Each environment refits and registers its own Unity Catalog version.

🏷️

Alias, then a pin

Aliases, not Workspace Model Registry stages. HTTP serving pins entity_version.

What stays switched off

🌙

Lights off

No all-purpose cluster and no SQL warehouse in the bundle. Serverless jobs. Scale-to-zero on the endpoint.

🚦

CI stays a check

CI does not deploy. CD does not run on push. Docs-only edits do not start CI.

What stays off the clipboard

🔐

Names in git

No secret tokens in git. Names live in .env.example. CI reads DATABRICKS_HOST and DATABRICKS_TOKEN from a variable group.

🧪

Tests without a workspace

Tests do not need a workspace. uv.lock is the install source. requirements.txt is the compiled file Databricks reads.

A red test stays free

These three lines are copied from azure-pipelines.yml.

displayName Validate Databricks bundle (no deploy)
CODE 
      databricks bundle validate -t develop
      databricks bundle validate -t ppe
      databricks bundle validate -t prod
PLAIN ENGLISH

Read the YAML for the develop target. Nothing is created or started, so a red result stays free.

The same read-only check for the ppe target.

The same read-only check for the prod target.

validate Reads YAML. A red test stays free.
deploy Creates or starts resources.
bundle run Creates or starts resources.

Two piles

What is still open sits in two piles.

💡
Same jobs, your own folders

Databricks publishes this shape as MLOps Stacks. You do not have to copy the template folder names. You do have to cover the same jobs: train, validate, register, deploy, serve, monitor.

This repo has train, register, and the descriptions of serve. Monitor is later.

Written and waiting on the $10 cost tracker

✅

Confirm YES

CD workflows that require confirm YES.

📐

Endpoint shape

The endpoint YAML is written. Creating it still waits on the cost approval.

🔌

Teardown notes

Teardown notes so spend can return to zero.

Later, or refused even if a template includes them

🗂️

Template extras

Feature tables, a dedicated Challenger validation job, inference tables, Lakehouse Monitoring, scheduled retrain.

🗺️

New region, new workspace

Separate workspaces per environment. A new Azure region means a new workspace. You cannot edit the region of an existing one.

🚫

Extra machines

A second orchestrator, Kubernetes, a separate web service, a GPU, or an always-on cluster.

🛑

Deploy inside the test

Putting bundle deploy inside the test workflow.

👀

A host just to peek

Filling a prod host just to see if validate works.
