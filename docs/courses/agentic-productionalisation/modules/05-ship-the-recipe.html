Infer waits for train

The job is two tasks. Train bakes and registers. Infer scores only after train has succeeded.

These lines are the infer task in databricks/jobs/iris_ml_job_pipeline.yml. The YAML is copied exactly.

CODE 
        - task_key: infer
          depends_on:
            - task_key: train
          spark_python_task:
            python_file: ../../notebooks/infer.py
PLAIN ENGLISH

Name this step infer. It is the scoring step.

It has a dependency. It starts only after that dependency succeeds.

The dependency is train. A failed train leaves infer unstarted.

Run a Python file as a Spark task.

The file is notebooks/infer.py, the scoring recipe.

✓

Train succeeds

Infer may score. This run uses the cake train just registered.

⏸

Train fails

Infer stays off. This job does not reach back for yesterday’s version.

Train’s save instructions are flags on train_register.py. They sit in badges so the infer lines stay exact.

--register Write a new version into Unity Catalog.
--alias Stick the alias from the variable ${var.model_alias} on that version.
--registered-name Use ${var.registered_model_name}, the three-level catalog name.
--env Pass ${var.env} so the run knows which kitchen it is.

Three kitchens, one recipe

One catalog, dbw_iris_ml_dev. Three schemas: develop, ppe, and prod. A model name stacks three levels: catalog, schema, model.

🥣

Develop kitchen

Schema develop. Endpoint develop-iris-species. Alias develop marks the version this kitchen trained.

🧁

PPE kitchen

Schema ppe, with its own endpoint name and the alias ppe. Same recipe, its own shelf.

🎂

Prod kitchen

Schema prod, endpoint prod-iris-species, alias prod. The recipe is the one on branch main.

🏷️
Environment alias

develop, ppe, or prod. It names the version that kitchen trained.

🧪
Challenger

Means the version passed validation. The task that updates this alias is not all built yet.

🏆
Champion

Means batch scoring should load this version. That alias-update task is not all built yet either.

All three targets share one workspace host today. Separate workspaces are later.

Prod writes its own name

Prod’s variables pin the branch, the model name, and the alias. The lines below are the variables from databricks/targets/prod.yml, copied exactly.

CODE 
    variables:
      env: prod
      git_branch: main
      env_prefix: prod
      registered_model_name: dbw_iris_ml_dev.prod.iris_species
      model_alias: prod

Copying the cake needs a written reason

Copying weights across catalogs is the exception. It needs an ADR. This teaching repo keeps a frozen album in git only so laptop tests have an input.
