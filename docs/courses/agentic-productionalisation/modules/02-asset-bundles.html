The manifest, not the forklift

The manifest lists what a warehouse may receive. It is not the forklift that unloads the truck.

In this repo that manifest is a DAB. The bundle is databricks.yml plus the YAML it includes.

What the include list leaves out

This block in databricks.yml is the permission slip for the manifest.

CODE 
include:
  # Serving endpoint stays in databricks/artifacts/ but is applied by CD via
  # `serving-endpoints create --no-wait`. Putting it in the bundle made
  # `bundle deploy` wait on container creation and blocked the job run.
  # Only the train-then-infer pipeline is deployed. Standalone train and
  # infer jobs never ran, so they are not in this bundle.
  - databricks/jobs/*.yml
  - databricks/targets/*.yml
PLAIN ENGLISH

The include list. Anything not named here stays outside the manifest.

The endpoint YAML is not in the include list. CD applies that file later.

serving-endpoints create --no-wait does the applying. It does not sit inside bundle deploy.

Bundle deploy must not wait on a serving container. That wait blocked the job run.

Only the job pipeline is in the bundle.

Jobs that never ran on their own stay off this list.

The job files are included. Deploy creates those jobs.

The target files are included. One manifest still names every environment.
